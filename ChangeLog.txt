SteamXBox - Change log
======================


4.6
---
  Identity

  * The application icon carries the wordmark under the emblem, on a rounded tile.

  Documentation

  * README rewritten. It described the Steam Controller bridge and the on-screen
    keyboard only, and had said nothing about the desktop environment, the search
    launcher, the tools, the document indexer or the support for controllers other
    than the Steam Controller.

  * PRESENTATION.md added: what the project is, who it is for, and how it is built.


4.5
---
  Desktop

  * The environment stays below every other window, whatever raises it. It covers the
    Windows desktop and nothing else, so a tool launched from it is never buried by it.
    Clicking a tile no longer brings the environment forward over your work.

  * The environment refuses to minimise, by any route. It is the backdrop, not a window
    to manage.

  * Tapping § twice clears the screen; tapping it twice again puts the windows back.
    Which way it goes is decided by looking at the screen, so restoring a window by hand
    does not send the shortcut the wrong way. As with Win+M, a few windows never
    minimise — an always-on-top overlay, a desktop widget, the Windows input panel.

  Search

  * Fixed: opening a folder from the launcher did nothing on some machines. Folders had
    been handed to explorer.exe by name, which on those machines starts and exits
    without opening anything, reporting success. They go to the shell again, and only
    fall back to the explorer if the shell refuses — which is what a cloud placeholder
    folder does.

  * Fixed: Ctrl+Enter, which shows an entry inside its folder, did nothing on those same
    machines. It now asks the shell directly rather than through the explorer's command
    line.

  * The launcher accepts typing on the very first summon. The caret used to arrive only
    from the second one, so the first use of the shortcut cost a click.

  Indexing

  * Office and OpenDocument templates are indexed — .dot, .xlt, .pot, .ott, .ots, .otp.
    A shared drive is full of them: invoices, payment schedules, forms, all holding the
    text somebody would search for.

  Identity

  * New application icon.


4.4
---
  Inputs

  * Every physical device is an independent input. Controllers no longer cancel each
    other: whichever one moves the pointer, moves it. The arbitration that froze the
    pointer whenever two controllers contributed in the same 8 ms window is gone, and
    with it the case where a trackpad still gliding on its inertia blocked another
    controller's stick for seconds at a time.

  * A controller that repeats an unchanged state no longer runs the whole mapping for
    it. A still controller still reports at 20 Hz, so held chords and inertia keep
    being told that time is passing.

  Sticks

  * The two sticks are tuned separately. Pointing and scrolling had shared one dead
    zone and one curve, so tuning either one spoiled the other.

  * Pointer speed, curve and dead zone are read from each controller's own profile
    instead of constants shared by every controller, and are editable in the Profils
    tab under "Stick droit : pointeur du bureau".

  * Fixed: saving a profile discarded any setting the clone in between did not know
    about. New settings silently reverted to their defaults on every save.

  On-screen keyboard

  * Pinned mode places the keyboard at the bottom centre of the screen holding the
    caret, rather than of the foreground window.

  * The floating keyboard keeps a gap from the text on both sides, and goes below the
    caret when there is no room to its left or above — the right is where the text is
    about to be written.

  Desktop

  * The environment no longer swallows clicks over its empty area, so other windows
    can be brought forward and it can go behind them.

  * It occupies the work area rather than the whole monitor, leaving the taskbar
    visible and usable.


4.0
---
  Interface

  * The interface is now available in English and French. It follows the Windows
    display language on first launch, and can be set explicitly in the Settings
    tab under "Language".

  * The startup option is now labelled "Start with Windows" and actually registers
    the application in the Windows Run key, instead of only recording a preference.

  * Settings that take a value are now percentage sliders rather than raw numbers.
    Left-pad settings sit on the left of the editor, right-pad settings on the right.

  * The window remembers its size per tab.

  * "Fine precision range" and "anti-brush distance" became fixed constants and are
    no longer exposed in the interface.

  * The "Default" profile now carries the reference settings and can be restored
    with "Restore default settings".

  * Per-pad vibration strength and rate are configurable, in percent, without
    affecting pointer or scroll motion.

  * The Overlay Keyboard section gained per-pad click vibration strength, replacing
    the cursor sensitivity setting. The general settings block above it was removed.

  Pad behaviour

  * Slow pointer movement no longer produces no motion at all: sub-pixel motion is
    accumulated instead of being truncated away.

  * Small gestures are scaled down by a distance-based precision ramp, so short
    corrections are finer without slowing down long sweeps.

  * Inertia after releasing the pad works again, with a direction-coherence check
    so a hesitant release no longer flings the pointer.

  * Scrolling is protected the same way: lifting the finger after an incoherent
    movement no longer scrolls backwards.

  * A pad click briefly makes the whole pad surface clickable, and press/release is
    preserved so windows can still be dragged and resized.

  * The profile editor's movement settings are read at runtime. Applying a profile
    takes effect without restarting.

  Overlay keyboard

  * Each pad drives its own cursor, split at the 6 / Z / H / N column.

  * Shift is three-state: one press for a single capital, two presses to lock.
    The physical Shift key is no longer held down, which used to leave the whole
    system stuck in uppercase.

  Diagnostics

  * Real logging with levels, categories and rotation, an effective-settings dump at
    startup, periodic counters instead of per-frame spam, and a "diag" CLI command.

  * The debug report reads versions from the binaries instead of a hard-coded
    string, which previously made it claim v2.3 while v3.0 was shipping.

  Xbox tab

  * The button mapping is editable. All 18 remappable buttons are exposed, laid out like the
    controller, and saved in their own named profiles. Steam and Quick Access stay fixed: they
    drive SteamXBox itself.

  * Menu now produces Start and View produces Back. They shipped inverted.

  * Stick dead zone, response curve and sensitivity; trigger threshold and full-press point;
    vibration enable, intensity and trackpad forwarding. Each of these controls existed in the
    interface before doing anything; each one now has a real effect.

  * Holding Menu and View together for three seconds powers the controller off. Neither button
    fires its own action on the way. SteamXBox unplugs the virtual pad and stands by, for as long
    as it takes, until the controller is switched back on.

  * An experimental trigger haptic channel, off by default. No trigger actuator has been confirmed
    on this firmware; "SteamXBox.Core.exe haptic-probe" sweeps the actuator indices to find out.

  * A Discord link sits at the bottom of the navigation rail, above the status cards.

  Fixes

  * Switching to Xbox360 mode holds. Automatic mode switching from the foreground window is now
    opt-in (--auto-mode) instead of always on: as a default it re-evaluated the foreground every
    750 ms and forced a mode from it, so a manual switch was undone as soon as focus moved, and a
    game that briefly stopped covering its monitor was dropped out of Xbox360 mode mid-session.
    When enabled, it now ignores the Windows compositor and shell surfaces, and requires four
    consecutive agreeing samples before acting.

  * Haptic feedback comes back after Steam closes. Releasing the controller to Steam reset the
    haptic device with a sentinel value that overflowed the reopen cooldown arithmetic, leaving
    haptics inert for the rest of the session once Steam had been opened even once.

  * Settings no longer revert each other. Every tab held its own copy of the settings and rewrote
    the whole file on save, so the last tab to save silently undid the others: the last used
    profile fell back to "Default" at the next launch, and "Start with Windows" did not stick.

  * The Windows startup entry is verified after being written, and the interface shows the command
    Windows will actually run, with a warning when it points at a different copy of SteamXBox.

  * Profile names containing spaces are passed to the runtime correctly.

  Packaging

  * The installers are available in English and French.

  * This README and change log replaced the NSSM documentation that had been shipped
    by mistake in previous packages.


Earlier versions
----------------
  Releases 1.0 through 3.2 were published without a change log. The packages remain
  available in the project's dist folder.
